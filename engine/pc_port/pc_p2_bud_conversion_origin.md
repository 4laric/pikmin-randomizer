# Typed source6 output provenance (#148 / #1281)

This component gives actual successful Black Candypop head emissions their own
typed identity. It does not add a GenPiki row, reuse positional matching, change
the immutable GenPiki map, or equate the campaign SHA with the Piki catalog SHA.
The head and its later plucked body share one conversion record. A same-colour
accepted donor refunds the bud budget but still emits and records a real head.

The record retains the actual selected retail floor incarnation separately from
the native original Pom identity: campaign/session, cave/floor, source/catalog/
layout hashes, visit, selected row/member/epoch/activation/instance, actual bud
UID/member/epoch/activation and successful emission ordinal. Donor authority
supplies a typed stable logical key while the real donor is alive. Addresses
never enter the wire format. Terminal donor and emission history survives scene
teardown; native pointer associations do not. A selected older SAVE restores
its complete authenticated history into a new provisional registry.

## Producer installation and physical lifecycle

After the real core binds a source6 Pom, and before it starts, install
`Producer::snapshotCallback` and `Producer::headCallback` through
`pc_p2_original_pom_set_head_callback`. Retain the Producer, Registry and
Authority until all callbacks stop. Its species callback must read the actual
initialized head. Its fatal callback must neither allocate nor throw: an
unexpected final adoption failure occurs after native consumption and must not
silently discard the head or invent provenance.

Snapshot prepares every map node, donor tombstone and output record before
consumption. It publishes nothing; capacity retry prepares again against the
current registry. The opaque local receipt is not a saved identity. The final
output callback checks exact core identity/token/ordinal/refund and actual head
species, then adopts with preallocated map nodes, without allocating. Existing
converted donors are retired by the real native kill before that callback.

Both native PikiHeadItem pluck routes prepare head-to-body transfer before
birth, use the explicit original field-limit entrypoint, and hold the exact
new-body initializer scope through native initialization. Final adoption moves
the same identity; old-head kill cannot retire the new body. Ordinary unlabelled
P1 heads keep their prior birth/initialization route. Native init exceptions and
actual counter conservation require physical fixture acceptance; pure controls
are not that evidence.

`pc_p2_source_body_query` distinguishes GenPiki, BudConversion and unavailable
authority. A converted body is source-nonwild/non-waswild, as FakePiki::onInit
clears both retail flags before head plucking. Expired proof retains the typed
label and refuses admission; it never falls back to ordinary P1 ownership. The
common contact/recruitment path uses the existing independent Progress authority.

## Actual floor/checkpoint owner obligation (still open)

Authority has no accepting implementation or default. Production integration
must use the native selected checkpoint reader as ProofSource and compare its
generation/full-card SHA, selected family bytes, campaign/session and owned
restore serial. Each bud or live-record lookup must invoke actual
SelectedFloorAuthority::expectedBirth, check that selected row is source6, and
check the native Pom catalog identity/token. Do not synthesize activation or
replace this with provider-created booleans. A parent bud may be dead while a
successful output remains alive; verify that output from the authenticated
family rather than requiring a live parent pointer.

SAVE carries the canonical BUD_LEDGER_1 family with every head, body and terminal
emission. Native successful SAVE may refresh the proof only when the complete
unchanged family bytes match the actual selected reader. Failed SAVE does not
refresh authority. Restore reserves all real heads/bodies and native identities,
resolves all provisional registry families, then publishes the registry through
the checkpoint GraphSDK provider's atomic publish phase. No ordinary birth,
budget callback or emission ordinal increment belongs in restore.

The current tests use explicit mock proof and opaque pointer identities. Actual
source6 native conversion, head-to-body plucking, across-frame collision to
Formation, full floor inventory and selected SAVE/fresh process roundtrip remain
unqualified. This module does not enable full-world Save & Quit.

## Fresh creation and ordinary RAM travel

`bindLive` uses a separate Creation record from the native owner, not a card
generation/hash. Installing permits callback registration after real family
binding; emission requires Committed and actual native gameplay activity.
Committed stopped capture remains allowed for the first SAVE. The native
OriginalSession adapter rechecks the actual selected campaign, immutable session
fingerprint/input and c482 monotonic selection revision. The final callback
checks that revision and the native floor serial without allocating.

RetailLiveFloorReader consumes NativeFloor 3e2 read APIs and originalActors'
actual source6 association/compiled floor row. NativeFloor revokes these APIs
before release. It reads original GameFlow movie/pause/UI/day-end activity;
actual frame behavior still needs the composed native test. The reader and
Authority belong to the FLOOR lifetime, never a single bud's lifetime. Terminal
parents use the retained actual native birth census. A different floor/epoch
requires the actual transition owner's retained graph, not a guessed parent.

Carry is an opaque one-use live transaction, separate from a cold checkpoint.
The source owner must approve its complete census/dispositions. Old pointers
are forgotten and the source cannot reopen while escrow is outstanding. An
empty actual new-serial destination validates every replacement body before
publishing the same complete history, without emission/pluck/activation. Failure
leaves the ticket available for recovery. Omitted bodies/heads may be retired
only when the actual transition owner confirms retirement; living old-floor
graph storage must go through that full graph owner, not this party-only path.

Cold restore and successful selected SAVE adoption still require full native
card proof. NativeLiveAuthority has no fake/default card reader. First real SAVE
adoption switches the live registry to selected-proof mode only after unchanged
family bytes and actual generation/SHA validation. Link the concrete retail
reader only with actual NativeFloor 3e2 and OriginalSession c482 dependencies;
the historical base does not supply those producers and keeps them disabled.
