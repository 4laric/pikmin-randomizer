## Required provider (exact)

- **Actor:** the `Pom` base actor born through the Pom family manager
  (parent-id resolution at `enemyInfo.h:204`). The colored id (3..8) comes
  from the generator record and selects the bud identity.
- **Must not:** spawn the base `Pom` (82) directly - `EFlag_CanBeSpawned` is
  absent (`enemyInfo.h:35` names Pom) and the id is documented
  "(crashes)" (`enemyInfo.h:141`).
- **Mesh/clip:** the converted Pom bank (lane 23) plus the per-species
  colored identity, replacing the Chappy proxy vehicle and its static bind
  pose.
- **Scope split:** the Pom actor/manager birth is family scope (flora/pom
  lane, issue #448). The generated-session placement binding is a shared
  generic provider owned by the placement shards - coordinate through #570,
  do not duplicate provider-shard work here.

## Exact markers that would flip gate 1 to natural PASS

For at least one colored bud, all four must appear in one fresh run's
native log, agreeing on the same generator and colored source id:

1. `P2_POM_BIND generator=<g> source_id=<3..8> host=pom`
   (a real Pom actor host, not `host=teki type=<n>`).
2. `P2_POM_DRAW generator=<g> source_id=<3..8> bank=pom pose=<clip>`
   (ordinary draw of the Pom bank with the colored identity).
3. `P2_SEED_RESOLVE source_id=<3..8>` (shared generated-session resolve).
4. `P2_GENERATED_PLACEMENT source_id=<3..8> target=<uid> generator=<g> bound=1`
   (shared generated-placement binding).

A verdict never flips a gate by itself: even with those markers this
remains a PASS *candidate* requiring integrator disposition (#437).
