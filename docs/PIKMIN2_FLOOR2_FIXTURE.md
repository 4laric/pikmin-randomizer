The driver prepares isolated profiles and runs three cases: cargo-free success, missing opt-in rejected for missing treasure, and conflicting cargo config rejected. The success case uses a real Research Pod model because native Purple setup requires a Pod receiver. `P2_POD_1 cargo_free 0 1 1 Kochappy 0` contains unused legacy treasure fields; no treasure actor/model or reward is supplied.

The fixture asserts the separate cargo-free readiness API, false treasure readiness, null treasure, zero cargo and Pokos, no `pr05` actors, and exact native flower IDs 62000/62001 at source positions. It injects normal engine throw calls toward both flowers without moving them or directly creating Purples. This is developer-driven conversion evidence, not manual play.
