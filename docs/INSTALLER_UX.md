# Installer UX and Open Nectar boundary

Tracking: #126. First pass, not a replacement for the native game menu.

## Player flow
Open the launcher, create a solo run or open the AP slot's seed, select a disc image once, and play. A fresh solo run requires no terminal or AP installation. AP multiworld generation remains the host's responsibility; the client needs the generated slot file to validate its identity and rules. Entering a server address alone cannot replace that file under the current protocol.

The starter solo preset has a random non-Trial start and color, normal stats, permanent checks, no traps, and the Emperor goal. A blank name creates a new seed; repeating a name selects the same deterministic seed/session. Existing seed files and saved sessions are not rewritten. Advanced option editing and host-side AP generation are later UI work.

## What can serve Open Nectar
Open Nectar already has a native installer with path selection, progress and error UI in engine/pc_port/launcher. Build on that entry point rather than submit the Pikipelago window wholesale.

- The bounded finalization retry (#125) is a small independent upstream candidate with a Windows lock test.
- Disc conversion/extraction progress and accurate errors are general installer concerns. launcher/discimage.py already takes an extractor path, installation root and validation callback. Its RVZ/WIA decoder could be a separate proposal after assessing packaging/dependency preferences upstream.
- Asset discovery, completed-install reuse, runtime dependency bundling and first-run instructions are shared requirements. Test with pristine user data and only packaged dependencies.
- Solo seed generation, AP slot files, connection state and randomizer saves belong to Pikipelago. Do not make them prerequisites of a vanilla Open Nectar install.

An in-game AP menu could eventually share the connection/session layer, but the first-run installer must work before game assets are available. Propose larger native UI changes to the upstream maintainer before implementation.

## AP module organization
The current world places option classes in __init__.py. Moving those to an Options.py module would improve navigation and review, but does not itself simplify installation. Treat it as a separate refactor, preserving option keys/defaults and package imports and validating generated YAML and fills. This audit does not claim that a particular filename is mandatory for AP compatibility.

## Validation scope
Focused launcher, real Tk widget, extraction, and AP protocol/reconnect tests. GUI tests invoke New solo run and verify persisted selection, and exercise AP/invalid-seed switching. A staged preview uses the public bundled runtime with candidate Python files overlaid locally. Windows UI capture currently rejects the autogenerated Python application identity, so full visual and interactive first-run acceptance remains outstanding. No published release artifact changed.

## Reused patterns from the ER and Bloodborne projects

Read-only reference review; no files were copied wholesale or changed in those checkouts.

- ER wizard, commit 8189e21be695567ab327b343867ce13ed1b638b5: wizard/wizard.html (preset selection/progressive disclosure around lines 7092-7175 and 7402-7415; durable explicit configuration around 5495-5520). Applied as a simple solo preset with its full manifest persisted; advanced CLI remains separate.
- ER client, shared client repo commit e769123da84a454e28d9d8f0c495fdf5a368d841: crates/standalone-egui/src/view.rs:174-205 and app.rs:245-323 keep connection/game/delivery status visible and override stale telemetry. Pikmin now surfaces connecting, connected, retry and refused states; full freshness telemetry remains future work.
- ER client config_watch.rs:28-178 (crates/eldenring-archipelago/src/) reconnects on changed connection settings while protecting against torn writes/echo loops. Pikmin adapts this to explicit reconnect over the runner's private stdin pipe, avoiding password storage. Seed/slot identity stays immutable; manifest mismatch remains fatal. Authentication refusal waits for correction instead of repeatedly submitting bad credentials.
- BB launcher, commit 3c3ee19658086db6fc3b5e8cd288ee94de16f472: bb_launcher/ui.py uses remembered seed, setup readiness and separate client health; doctor.py/readiness.py gather structured evidence. Applied as collapsed completed setup, Continue with recorded check count, and an allowlist diagnostic report. Exact saved day/area is not inferred from the opaque native checkpoint; the card's area remains explicitly the starting area.
- Shared crates/shared/src/connect_error.rs:39-187 distinguishes transport failures from login errors. Pikmin preserves that boundary and does not treat a manifest error as a recoverable credential error.

Additional recovery: each RVZ/WIA decode gets a unique temporary ISO. A prior interrupted decode is never mistaken for a completed image; failed current attempts remove only their own temporary file. Orphaned files from a killed process are preserved rather than deleted without ownership evidence.

Follow-up validation: 43 focused tests pass, including corrected-credential reconnect with the same live session, fatal seed mismatch despite queued reconnect, private-pipe parsing, no credential persistence, setup collapse/change, diagnostic privacy, and interrupted-decode isolation. Full visual acceptance remains outstanding; this remains a draft.
