# Purple impact and dwarf stun proposal

Issue #120. Source-only batch; no native behavior changed. Reproducible extraction: `python -m experimental.pikmin2_kochappy_stun_reference --reference output/p2-dwarf-red-profile/validated/kochappy-profile.json --research native/pikmin2-research --output output/p2-red-purple-stun/reference.json`. Output retains source/profile SHA256 values. Three reference tests cover strict timing/chance boundaries, landing delay, retained timer, interruption and invalid numbers.

## Source behavior

Audited retail fp36/fp37/fp38 are50damage/0.3chance/10seconds for Kochappy Red,50/0.3/5 for Snow and Orange. These are three different concerns: the50damage is generic hipdrop fallback, not automatically damage to a Dwarf. InteractHipdrop calls pressCallBack first; KochappyBase accepts living non-bitter Piki press and enters its Press state. Nearby earthquake is a separate interaction generated by PikiHipDropState::earthquake using the source PoundAOERange and custom-radius cell iterator.

EnemyBase::earthquakeCallBack requires a floor triangle, living/nondead/nonflying actor and rejects hard constraint, bitter, no-interrupt and bitter-immune conditions. It enters Earthquake, which stops motion and gives Y velocity200*bounceFactor+100*random. Only after more than3 updates and ground contact does it choose Fit: retained positive stun timer, or random strictly less than0.3 without bitter-queued/no-interrupt. Fit advances elapsed delta time; it exits strictly after duration, or on death/bitter-queued. Repeated earthquake does not restart an already positive timer. Fit freezes source motion and velocity, but is a lifecycle state rather than a total actor update freeze.

## Current port gap

pc_p2_purple.cpp implements identity, source movement/carry/attack/throw values and sampled models. It has no hipdrop/earthquake/stun callback. PikiFlyingState::procBounceMsg returns to Normal/native situation action; procCollideMsg follows P1 collision behavior. InteractPress::actTeki generates native Pressed, not an earthquake. Red's existing profile supplies health200 and visuals only. Simply changing a timer field would have no gameplay effect.

BTeki::doAI invokes the shared native strategy; its actions also handle damage/death. Skipping the whole strategy for10seconds risks making a stunned enemy ignore lethal damage. mIsFrozen would also conflate debug scheduling with a gameplay state. Neither is an acceptable shortcut. Health parameters must remain peractor and corpses must continue their existing path.

## Proposed next bounded native slice (approval required)

First add an opt-in Purple landing-event receiver and earthquake/Fit policy for registered living Kochappy Red only, with separate peractor state in a NEW pc_p2_kochappy_stun.cpp/.h and portable policy header. A unique landing token prevents duplicate bounce/collision dispatch. Native P1 defaults and Snow remain untouched until separately enabled. The event takes source roll/bounce inputs, records airborne/landing steps and elapsed Fit time; tests use deterministic rolls while gameplay uses native RNG. Do not add generic50damage to the already accepted direct press path.

Requested hooks to audit/approve before writing: pc_p2_purple.cpp/.h (armed thrown-Purple landing emitter), pikiState.cpp only PikiFlying bounce/collision receivers (emit once), pc_p2_kochappy.cpp/.h (registered identity/lifecycle forget/reset delegation), and taichappy.cpp or taireactionactions.cpp for an explicit peractor stun action that preserves damage and death processing. BTeki animation draw can read the active stun timer, but no global strategy or parameter table mutation. Root owns CMake and any common Snow integration. The exact action insertion point must be established with a lethal-damage-during-stun regression before enabling real gameplay; no unreviewed BTeki::doAI early return.

Prerequisites for that native slice: extract numeric retail PoundAOERange and actual custom-radius predicate, audit P1 Chappy action ordering to keep lethal damage active, map the supported eligibility flags explicitly instead of inventing P2 flag equivalence, and provide a Purple-enabled Pod fixture (current Purple setup requires Pod). Current original-map Red arena deliberately has no Pod, so enabling Purple there is a separate reviewed fixture contract change.

Acceptance: one thrown Purple triggers once; out-of-range/ordinary Piki/nonregistered/corpse ignored; source roll0.299 succeeds and0.3fails; live Red recovers after strictly10seconds; repeated impacts retain elapsed timer; lethal damage creates normal corpse while stunned; cleanup/rebirth clears state; control health/AI untouched. Full earthquake effects, source Press FSM, exact P2 locomotion and Snow5second gameplay remain outside the first slice. Feasibility is moderate, with missing emitter plus safe damage-preserving receiver as the real work, not the10second scalar.
