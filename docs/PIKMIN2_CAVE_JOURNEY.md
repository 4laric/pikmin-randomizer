# #1127 transition contract v1, before implementation

Opt-in package schema3 policy forest1-two-floor-journey-v1; canonical journey schema1 contains seed/slot and two independently deterministic floor descriptors with salts0/1. Journey fingerprint pins both descriptors and salts; package hashes pin both generated layout/geometry inputs and executables. Legacy schema2 packages remain same-floor and retain original descriptor hashes.

session/state.json is the sole atomic authority: schema1, journey fingerprint, floor1or2, revision0or1, current entry (health, exact ordered species/maturity squad, destination bud state), and at most one immutable source boundary record. Initial state is the ordinary20Red1 leaf baseline, health1, source floor1, no incoming transfer. A native floor1 P2_CAVE_TRANSFER_1(token=floor1 fingerprint32,floor1) with its actual matching bud transfer and durable source ledger is validated before atomic state replacement to floor2/revision1. Source boundary stores exact transfer/buds/ledger hashes/text and run identity; destination entry contains the exact survivors/health, floor2's independent zero bud budgets. This is new destination bud identity, not a restored/reset source budget. No source-floor re-entry/reward replay after commit.

Each floor has its own durable ledger in session; ledgers exist before initial state and are never silently recreated once state or pending exists. Reads validate native seed, floor-specific reward/host identities, event type and duplicate entries. Source receipt ledger remains preserved after transition; destination ledger starts empty once and must stay valid. Source budgets remain in boundary record; destination budget remains independent and is restored on later floor2 launches. No shared bud/receipt identities between floors.

pending.json records journey fingerprint, exact source state revision/floor, unique run path beneath session/runs, input entry/descriptor/layout hashes and executable path. It is written before process launch while holding OS session lock. The same lock spans child lifetime and boundary commit. Recovery checks the exact child executable is not running, validates pending and pinned run files, then validates actual transfer. If state still has source revision, commit the transition once; if state already records that run/boundary at destination revision, verify equal source bytes and clear pending without another advancement. Missing transfer means an unsaved exit: validate durable ledgers and keep the existing boundary squad/floor. Invalid transfer/state or a living same-session child refuses launch. Never reset a failed/empty squad to starters. Crash after native42 but before atomic replacement is recoverable from complete native transfer/bud files plus durable ledger; incomplete/foreign bytes fail closed.

Floor2 is observation/re-entry for this bounded slice. Automatic descent stops after one native floor1 boundary and launches floor2; no floor3 and no terminal surface/geyser return claim. Normal quit on floor2 preserves the last incoming boundary squad and receipts. No fabricated checkpoint is accepted as compiled proof; tests may use synthetic protocol bytes only for malformed/recovery unit coverage. Automated acceptance uses bounded60s native children, fresh ordinary stage and mapped controller traversal, actual native42 transfer, production supervisor commit, and two separate floor2 observations (initial and restart). UI confirmation bypass remains explicitly disclosed, not actual F6/manual confirmation acceptance.
