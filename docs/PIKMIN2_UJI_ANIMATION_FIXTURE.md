# Uji animated runtime acceptance

NEW host installer: experimental.pikmin2_uji_animation_install validates the complete imported bank before writes: fixed species/clip mapping, exact safe filenames, integer ordered frames/endpoints, pose SHA256 and length, shared resource chunks, clip/total byte caps. Installation requires an existing private Sheargrub stage and refuses preexisting destinations. It copies frozen validated bytes and emits the strict native protocol plus install hashes. It does not modify production staging.

NEW private driver: experimental.pikmin2_uji_animation_fixture first uses the maintained strict snapshot builder, then privately compiles an instrumented copy of pc_p2_sheargrub.cpp. It replaces only that family object in the private captured link. The original and instrumented hashes, compiler/link commands and before/after input/freshness checks are retained. Instrumentation only logs selected clip, pose and native motion once per combination; it changes no behavior. No production telemetry hooks are added.

The run matrix prepares separate static and animated stages using the grounded ten-Uji fixture. Both must pass ten native birth positions, legitimate emergence/attacks, ten corpses crossing the connector, exact14Poko receipts and unchanged repairs. Animated rendering must show changing poses for each species and a source dead corpse pose; static fallback must render both living and dead actors. Existing fixture captures provide visual inspection artifacts. This does not claim every motion exercised, manual combat QA, or P2 behavior fidelity. Source sampled visuals retain P1 proxy gameplay.

Build CLI: python -m experimental.pikmin2_uji_animation_fixture build --native native --build-dir native/build-randomizer --output PRIVATE --head FULL_FRESH_HEAD. Run CLI takes --assets --assembly --pod --content --uji --output --exe --bank. Animation acceptance JSON is per-run only after all gates pass.
