# Second Violet observation

The cargo-free floor 2 fixture currently reaches five Purple sprouts while the other flower remains in state 3. This diagnostic adds observations only to the frozen input driver, with source flowers and throw behavior unchanged. It does not propose a production fix before evidence identifies the failed transition.

Each 150-frame sample records both flowers' state, life status, attached count, previous attached count, released and maximum count, walk timer, animation speed, motion and frame. It also records every original Pikmin's life/state, attachment pointer/type and position. Read-only explicit-template member pointers expose private counters in the private fixture; production headers and class layout are unchanged.

Source control flow is in `native/src/plugPikiNishimura/PomAi.cpp`: `checkSwayAndScale` refreshes the prior stick count, states 2/3 both call `calcPetalStickers`, and `petalCloseTransit` tests capacity or walk timer. `calcPetalStickers` increments the timer only after `mIsPikiOrPlayerTouching` is set, and converts attached actors to swallowed state. `Pom.cpp::collisionCallback` sets that contact flag. `createPikiHead` dispatches the Violet conversion helper; no direct helper call occurs in this diagnostic.

Build with `py -3.12 -m experimental.pikmin2_violet_diagnostic --native native --build native/build-randomizer --output <private-output> --expected-head <stable-native-SHA>`. Runtime uses the existing floor 2 fixture driver with this executable. Source snapshots, compiler/link inputs and provenance are recorded by the shared private fixture builder. No shared build, export or live save is involved.

First observed result (output/p2-violet-diagnostic/validation01/runs/d46f334befce4de59e37afbf4863ca1d): flower0 remains alive in state3 with sticks0, previous0, released0/max5 and walk timer0.000; intended inputs remain alive/Normal/unattached near its source transform. Flower1 accepts swallowed inputs and reaches released5/max5, then dies normally. This rules out a full/occupied flower waiting on conversion; the stalled branch has no accepted contact. World collision/eligibility observation is the next targeted step.

Root cause established by collision probe at output/p2-violet-diagnostic/validation02/runs/c5036e1976234ac79655f7c419b82f35: native flower0 is (-55,215,75), collider centerY235.7; flower1 is (75,45,-95). Source Y is0; source yaw values215/45 were written into the generic second vector. Generator::read (native/src/plugPikiKando/generator.cpp:781-791) reads position then mGenOffset, and Generator.h:960 getPos adds them. Thus the host incorrectly treated an additive offset as rotation. This is a host staging defect, not a flower conversion failure. The same nonzero-angle writer occurs in pikmin2_beasts_uji.py and pikmin2_roster.py; their source-transform claims require audit. Fix proposal: zero generic offsets, retain source yaw as explicitly unapplied until a supported actor-specific orientation path exists, and validate effective XYZ both decoded and native.
